\chapter{واجهات نظام التشغيل}
\label{CH:UNIX}

تتمثل وظيفة نظام التشغيل في مشاركة جهاز الحاسوب بين برامج متعددة وتوفير مجموعة من الخدمات أكثر فائدة مما يدعمه العتاد بمفرده. يقوم نظام التشغيل بـ إدارة وتجريد العتاد منخفض المستوى، بحيث لا يحتاج برنامج معالج النصوص مثلاً إلى الاهتمام بنوع عتاد القرص الصلب المستخدَم. كما يشارك نظام التشغيل العتاد بين برامج متعددة لتعمل (أو تبدو وكأنها تعمل) في آنٍ واحد. وأخيرًا، توفر أنظمة التشغيل وسائل محكومة للبرامج للتفاعل فيما بينها، بحيث يمكنها مشاركة البيانات أو العمل معًا.

يوفر نظام التشغيل خدماته لبرامج المستخدم من خلال واجهة محددة.
\index{تصميم الواجهات}
ويتضح أن تصميم واجهة جيدة هو تحديًا هندسيًا بالغ الدقة. فمن ناحية، نود أن تكون الواجهة بسيطة وضيقة لأن ذلك يسهل التحقق من صحة التنفيذ. ومن ناحية أخرى، قد نغري أنفسنا بتقديم العديد من الميزات المعقدة للتطبيقات. وتكمن المهارة في حل هذا التجاذب في تصميم واجهات تعتمد على آليات قليلة يمكن دمجها لتوفير قدر كبير من العمومية والمرونة.

يستخدم هذا الكتاب نظام تشغيل واحدًا كـ مثال عملي ملموس لتوضيح مفاهيم أنظمة التشغيل. هذا النظام، وهو \textbf{xv6}، يوفر الواجهات الأساسية التي قدمها نظام التشغيل Unix الذي طوره كين ثومبسون ودينيس ريتشي~\cite{unix}، كما يحاكي التصميم الداخلي لـ Unix. يوفر Unix واجهة ضيقة تندمج آلياتها بشكل ممتاز، مما يمنح درجة مفاجئة من العمومية. وقد حققت هذه الواجهة نجاحًا باهرًا لدرجة أن أنظمة التشغيل الحديثة — مثل BSD و Linux و macOS و Solaris، وحتى Microsoft Windows بدرجة أقل — تمتلك واجهات شبيهة بـ Unix. ويُعد فهم xv6 بداية ممتازة لنحو فهم أي من هذه الأنظمة والعديد غيرها.

وكما يظهر في الشكل~\ref{fig:os}، يأخذ xv6 الشكل التقليدي لـ
\indextext{النواة} (kernel)،
وهي برنامج خاص يوفر الخدمات للبرامج قيد التشغيل.
يُطلق على كل برنامج قيد التشغيل اسم
\indextext{عملية} (process)،
وتملك كل عملية ذاكرة تحتوي على التعليمات والبيانات والمكدس (stack). تنفذ التعليمات الحسابات الخاصة بالبرنامج. والبيانات هي المتغيرات التي تعمل عليها الحسابات. بينما ينظم المكدس استدعاءات الإجراءات داخل البرنامج. ويحتوي الحاسوب عادةً على العديد من العمليات ولكن على نواة واحدة فقط.

عندما تحتاج عملية ما إلى استدعاء خدمة من خدمات النواة، فإنها تقوم بإجراء
\indextext{استدعاء نظام} (system call)،
وهو أحد الاستدعاءات المتاحة في واجهة نظام التشغيل.
يدخل استدعاء النظام إلى النواة؛ فتقوم النواة بتنفيذ الخدمة المطلوبة ثم تعود إلى العملية.
وبذلك تتناوب العملية بين التنفيذ في
\indextext{فضاء المستخدم} (user space)
و
\indextext{فضاء النواة} (kernel space).

تستخدم النواة آليات الحماية العتادية التي توفرها وحدة المعالجة المركزية (CPU)
لتضمن أن كل عملية تنفذ في فضاء المستخدم لا يمكنها الوصول إلا إلى ذاكرتها الخاصة.
تنفذ النواة بالصلاحيات العتادية المطلوبة لتطبيق هذه الحمايات؛ بينما تنفذ برامج المستخدم بدون تلك الصلاحيات.
عندما يستدعي برنامج مستخدم استدعاء نظام، يرفع العتاد مستوى الصلاحية ويبدأ في تنفيذ دالة تم إعدادها مسبقًا داخل النواة.

يرسم بقية هذا الفصل الخطوط العريضة لخدمات xv6 — العمليات، الذاكرة، واصفات الملفات، الأنابيب، ونظام الملفات — ويوضحها بمقاطع برمجية ومناقشات حول كيفية استخدام
\indextext{الشِل} (shell)،
وهو واجهة المستخدم التفاعلية عبر السطر الأوامري في Unix. يوضح استخدام الشِل لاستدعاءات النظام مدى الدقة التي تم بها تصميم هذه الواجهات.

الشِل هو برنامج عادي يقرأ الأوامر من المستخدم وينفذها.
وحقيقة أن الشِل هو برنامج مستخدم وليس جزءًا من النواة يوضح قوة واجهة استدعاءات النظام: فلا يوجد شيء فريد أو خاص في الشِل.
وهذا يعني أيضًا أنه من السهل استبدال الشِل؛ ونتيجة لذلك، تحتوي أنظمة Unix الحديثة على مجموعة متنوعة من الشِلات للاختيار من بينها، ولكل منها واجهة مستخدم وميزات برمجية خاصة.

\section{العمليات والذاكرة}

العملية في xv6 تتكون من فضاء ذاكرة (أو فضاء عناوين افتراضي) وسلسلة من خيوط التنفيذ المدارة بواسطة النواة.
يوفر xv6 زمن تنفيذي متضمنًا العزل بين العمليات: تمنع النواة أي عملية من الوصول إلى الذاكرة الخاصة بعملية أخرى.

تستخدم العملية استدعاء النظام \lstinline{fork} لإنشاء عملية جديدة.
يعطي \lstinline{fork} العملية الجديدة نسخة مطابقة تمامًا لذاكرة العملية المستدعية: ينخ \lstinline{fork} التعليمات، والبيانات، والمكدس الخاص بالعملية المستدعية إلى ذاكرة العملية الجديدة.
يعود الاستدعاء \lstinline{fork} في كل من العملية الأصلية والعملية الجديدة.
في العملية الأصلية (الأب)، يعيد \lstinline{fork} معرّف العملية الابن (PID).
أما في العملية الجديدة (الابن)، فيعيد \lstinline{fork} الصفر.

يوضح المقطع البرمجي الآتي الاستخدام المباشر لـ \lstinline{fork} و \lstinline{wait}:
\begin{lstlisting}
int pid = fork();
if(pid > 0){
  printf("parent: child=%d\n", pid);
  pid = wait((int *) 0);
  printf("child %d is done\n", pid);
} else if(pid == 0){
  printf("child: exiting\n");
  exit(0);
} else {
  printf("fork error\n");
}
\end{lstlisting}

قد تكون مخرجات هذا الكود بالشكل الآتي:
\begin{lstlisting}
parent: child=1234
child: exiting
\end{lstlisting}
تليها السطر التالي بعد انتهاء الابن:
\begin{lstlisting}
parent: child 1234 is done
\end{lstlisting}

يقوم استدعاء النظام \lstinline{exec} بتعويض فضاء الذاكرة الخاص بالعملية المستدعية بصورة جديدة مأخوذة من ملف تنفيذي مُخزن في نظام الملفات:
\begin{lstlisting}
char *argv[3];

argv[0] = "echo";
argv[1] = "hello";
argv[2] = 0;
exec("/bin/echo", argv);
printf("exec error\n");
\end{lstlisting}

\section{الإدخال/الخرج وواصفات الملفات}

\indextext{واصف الملف} (file descriptor) هو رقم صحيح صغير يعبر عن كائن مفتوح بواسطة العملية يمكن القراءة منه أو الكتابة فيه.
اصطلاحًا، تقرأ العملية من واصف الملف 0 (الإدخال القياسي)، وتكتب المخرجات إلى واصف الملف 1 (الإخراج القياسي)، وتكتب الأخطاء إلى واصف الملف 2 (الخطأ القياسي).

يوضح المثال التكرار الأساسي للقرأة والكتابة:
\begin{lstlisting}
char buf[512];
int n;

for(;;){
  n = read(0, buf, sizeof buf);
  if(n == 0)
    break;
  if(n < 0){
    fprintf(2, "read error\n");
    exit(1);
  }
  if(write(1, buf, n) != n){
    fprintf(2, "write error\n");
    exit(1);
  }
}
\end{lstlisting}

تتيح آلية إعادة توجيه الإخراج والإدخال للشِل الاستفادة من واصفات الملفات المغلقة والمفتوحة حديثًا:
\begin{lstlisting}
char *argv[2];

argv[0] = "cat";
argv[1] = 0;
if(fork() == 0) {
  close(0);
  open("input.txt", O_RDONLY);
  exec("cat", argv);
}
\end{lstlisting}

وتوضح الميكانيكية التالية استخدام النسخ عبر \lstinline{dup}:
\begin{lstlisting}
fd = dup(1);
write(1, "hello ", 6);
write(fd, "world\n", 6);
\end{lstlisting}

\section{الأنابيب}

\indextext{الأنبوب} (pipe) هو قناة تدفق بيانات صغيرة تُعرض للعمليات في صورة زوج من واصفات الملفات: واحد للقراءة والآخر للكتابة.
الكتابة في أحد طرفي الأنبوب تجعل البيانات متاحة للقراءة من الطرف الآخر.

\begin{lstlisting}
int p[2];
char *argv[2];

argv[0] = "wc";
argv[1] = 0;

pipe(p);
if(fork() == 0) {
  close(0);
  dup(p[0]);
  close(p[0]);
  close(p[1]);
  exec("/bin/wc", argv);
} else {
  close(p[0]);
  write(p[1], "hello world\n", 12);
  close(p[1]);
}
\end{lstlisting}

تتيح الشِلات توصيل الأوامر مثل:
\begin{lstlisting}
echo hello world | wc
\end{lstlisting}
أو إعادة توجيه الملفات:
\begin{lstlisting}
echo hello world >/tmp/xyz; wc </tmp/xyz
\end{lstlisting}

\section{نظام الملفات}

يوفر نظام الملفات في xv6 ملفات بيانات معنونة بأسماء ومُنظمة داخل شجرة من الدلائل (directories).
\begin{lstlisting}
mkdir("/dir");
fd = open("/dir/file", O_CREATE|O_WRONLY);
close(fd);
mknod("/console", 1, 1);
\end{lstlisting}

تُعرف العقدة الميتاداتا لملف في نظام الملفات عبر الهيكل \lstinline{struct stat}:
\begin{lstlisting}
#define T_DIR     1   // دليل
#define T_FILE    2   // ملف
#define T_DEVICE  3   // جهاز

struct stat {
  int dev;     // جهاز القرص
  uint ino;    // رقم Inode
  short type;  // نوع الملف
  short nlink; // عدد الوصلات الصلبة
  uint64 size; // حجم الملف بالبايتات
};
\end{lstlisting}

تتيح الوصلات الصلبة تسمية ملف بأسماء متعددة:
\begin{lstlisting}
open("a", O_CREATE|O_WRONLY);
link("a", "b");
\end{lstlisting}
وعند استدعاء \lstinline{unlink("a")} يتم حسم الاسم الأول مع الإبقاء على الملف المتاح باسم \lstinline{b}.

\section{العالم الحقيقي}

تستعرض الواجهات المعروضة في xv6 الأساس المحوري لأنظمة التشغيل الحديثة المعتمدة على معايير POSIX (مثل Linux و macOS و FreeBSD).
