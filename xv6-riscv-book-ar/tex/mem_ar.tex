\chapter{جداول الصفحات}
\label{CH:MEM}

جداول الصفحات هي الميكانيكية الأساسية التي يقدمها العتاد وتعتمد عليها النواة لتوفير الذاكرة الافتراضية وتحقيق العزل بين العمليات.
تسمح جداول الصفحات لنظام التشغيل برسم خريطة العناوين الافتراضية المشتغلة عليها البرامج وتحويلها إلى عناوين فيزيائية فعلية في ذاكرة الحاسوب (RAM).

يقدم هذا الفصل كيفية تنظيم جداول الصفحات في معمارية RISC-V SV39، وتخطيط الذاكرة لكل من النواة والعمليات في xv6، وكيفية تخصيص وتحرير الذاكرة الفيزيائية.

\section{عتاد التصفح}

تستخدم معمارية RISC-V 64-bit نمط تصفح يُدعى \textbf{Sv39}، حيث تُستخدم 39 بتًا فقط من أصل 64 بت في العنوان الافتراضي.
يتم تقسيم الذاكرة إلى كتل ثابتة تُسمى \indextext{الصفحات} (pages)، ويبلغ حجم الصفحة الواحدة 4096 بايت (4 كيلوبايت).

يتكون العنوان الافتراضي ذو الـ 39 بت في Sv39 من:
\begin{itemize}
\item 27 بت تعبر عن \indextext{رقم الصفحة الظاهرية} (Virtual Page Number - VPN)، وتُقسم إلى ثلاثة مستويات بعرض 9 بتات لكل مستوى (VPN[2]، VPN[1]، VPN[0]).
\item 12 بت تعبر عن \indextext{الإزاحة} (Offset) داخل الصفحة ($2^{12} = 4096$ بايت).
\end{itemize}

يتكون جدول الصفحات في Sv39 من هيكل شجري ثلاثي المستويات:
\begin{enumerate}
\item يحتفظ السجل العتادي \lstinline{satp} (Supervisor Address Translation and Paging) بالعنوان الفيزيائي لجدول الصفحات من المستوى الأعلى (Level 2).
\item تستخدم وحدة إدارة الذاكرة (MMU) الـ 9 بتات الأهم (VPN[2]) لفهرسة الجدول الأول للحصول على عنوان جدول المستوى التالي.
\item تُستخدم الـ 9 بتات الوسطى (VPN[1]) لفهرسة جدول المستوى الثاني.
\item تُستخدم الـ 9 بتات الأدنى (VPN[0]) لفهرسة جدول المستوى الثالث للحصول على \indextext{مدخل جدول الصفحات} (Page Table Entry - PTE).
\end{enumerate}

يحتوي مدخل جدول الصفحات (PTE) ذو الـ 64 بت على رقم الصفحة الفيزيائية (Physical Page Number - PPN) ورايات التحكم والتحقق (Flags):
\begin{itemize}
\item \lstinline{PTE_V} (Valid): يحدد ما إذا كان المدخل صالحًا وموجودًا.
\item \lstinline{PTE_R} (Readable): يسمح بقراءة الصفحة.
\item \lstinline{PTE_W} (Writable): يسمح بالكتابة في الصفحة.
\item \lstinline{PTE_X} (Executable): يسمح بتنفيذ التعليمات من الصفحة.
\item \lstinline{PTE_U} (User): يحدد إمكانية الوصول للصفحة من وضع المستخدم (U-mode).
\end{itemize}

لتسريع ترجمة العناوين وتجنب الوصول المكرر للذاكرة، يحتوي المعالج على «مخزن الترجمة المؤقت (Translation Lookaside Buffer، TLB)». وعند تعديل جدول الصفحات، يجب على النواة فرز ومسح مخزن الترجمة المؤقت باستخدام تعليمة \lstinline{sfence.vma}.

\section{فضاء عناوين النواة}

يقوم xv6 بإعداد \indextext{فضاء عناوين النواة} (kernel address space) لتمكين النواة من الوصول إلى العتاد والأجهزة الملحقة والذاكرة المادية.
يستخدم xv6 التعيين المباشر (Direct Mapping) لمعظم الذاكرة الفيزيائية داخل النواة:
\begin{itemize}
\item العناوين من \lstinline{0x00000000} إلى \lstinline{0x80000000} تُخصص لمتحكمات الأجهزة والملحقات العتادية (مثل UART، PLIC، ومتحكمات virtio).
\item العنوان \lstinline{0x80000000} هو بداية الذاكرة الفيزيائية الرئيسية (RAM). تُعين النواة كودها وبياناتها بدءًا من هذا العنوان.
\item يتواجد أقصى عنوان في الذاكرة المادية عند \lstinline{PHYSTOP} (\lstinline{0x88000000}، بحد أقصى 128 ميجابايت في xv6).
\end{itemize}

هناك استثناءان مهمان للتعيين المباشر في فضاء عناوين النواة:
\begin{enumerate}
\item \textbf{صفحة المنصة القافزة (Trampoline Page)}: تُعين عند أعلى عنوان افتراضي ممكن (\lstinline{MAXVA - PGSIZE}) لتمكين التحويل بين فضاء المستخدم وفضاء النواة.
\item \textbf{مكدسات النواة (Kernel Stacks)}: تُخصص لكل عملية مكدس نواتي خاص مع وضع \indextext{صفحة حارس} (Guard Page) غير صالحة تحته مباشرةً لاكتشاف طفح المكدس (Stack Overflow) والتسبب في خطأ حماية فورية.
\end{enumerate}

\section{الكود البرمجي: إنشاء فضاء العناوين}

تُدار جداول الصفحات في xv6 عبر البرمجية \lstinline{kernel/vm.c}.
الدالة الأساسية للبحث والتنقل في شجرة جداول الصفحات هي \lstinline{walk()}:
\begin{lstlisting}
pte_t *
walk(pagetable_t pagetable, uint64 va, int alloc)
\end{lstlisting}
تقوم \lstinline{walk()} بتطبيق عملية الترجمة ثلاثية المستويات عتاديًا وبرمجيًا. إذا كان خيار \lstinline{alloc} مفعلًا ولم يكن جدول الصفحات الفراعي موجودًا، تقوم \lstinline{walk()} بتخصيص صفحة جديدة باستخدام \lstinline{kalloc()}.

وتوفر الدالة \lstinline{mappages()} آلية ربط نطاق من العناوين الافتراضية بالعناوين الفيزيائية عن طريق إضافة المداخل المناسبة عبر \lstinline{walk()}.

\section{تخصيص الذاكرة الفيزيائية}

تحتاج النواة إلى تخصيص وتحرير صفحات الذاكرة المادية بكتل حجمها 4096 بايت أثناء التشغيل لخدمة جداول الصفحات ومكدسات العمليات والذاكرات المؤقتة.

تُدار الذاكرة الفيزيائية الحرة بين نهاية كود النواة (\lstinline{end}) وأقصى الذاكرة (\lstinline{PHYSTOP}) بواسطة \indextext{مخصص الذاكرة الفيزيائية} (Physical Memory Allocator).

\section{الكود البرمجي: مخصص الذاكرة الفيزيائية}

يتواجد مخصص الذاكرة في \lstinline{kernel/kalloc.c}.
يحتفظ المخصص بقائمة متصلة أحادية من الصفحات الحرة (\lstinline{struct run}):
\begin{lstlisting}
struct run {
  struct run *next;
};

struct {
  struct spinlock lock;
  struct run *freelist;
} kmem;
\end{lstlisting}
تضمن \lstinline{spinlock} التزامن ومنع حالة التسابق (Race Condition) عند تخصيص أو تحرير الصفحات بين أنوية المعالج المختلفة:
\begin{itemize}
\item \lstinline{kalloc()}: تسحب صفحة حرّة من رأس القائمة \lstinline{freelist} وتعيد عنوانها الفيزيائي بعد تعبئته بقيمة مخفية خردة (\lstinline{1}) لاكتشاف الأخطاء.
\item \lstinline{kfree(pa)}: تتأكد من صحة العنوان الفيزيائي، وتكتب فيه بيانات خردة (\lstinline{1}) لمنع استخدام الذاكرة المحررة، ثم تعيد الصفحات إلى أصل القائمة \lstinline{freelist}.
\end{itemize}

\section{فضاء عناوين العملية}

تملك كل عملية في xv6 جدول صفحات مستقل يمثل فضاء عناوينها الظاهري.
يبدأ فضاء عناوين العملية من العنوان الافتراضي \lstinline{0x0}:
\begin{itemize}
\item التعليمات والبيانات والمكدس الابتدائي تبدأ من العنوان \lstinline{0x0}.
\item ينظر مكدس المستخدم إلى الأسفل ويتم توسيعه تلقائيًا.
\item تعلو القمة المتحركة للذاكرة الديناميكية للعملية (\lstinline{heap}) وتُوسع بواسطة استدعاء النظام \lstinline{sbrk()} المعتمد على الدالة \lstinline{growproc()}.
\item في أعلى فضاء العناوين الممكن (\lstinline{MAXVA})، تقع صفحة المنصة القافزة (\lstinline{TRAMPOLINE}) وتحتها مباشرة صفحة إطار المصيدة (\lstinline{TRAPFRAME}).
\end{itemize}

\section{الكود البرمجي: exec}

يقوم استدعاء النظام \lstinline{exec()} بالخطوات التالية لتشغيل برنامج جديد:
\begin{enumerate}
\item يفتح الملف التنفيذي المنسق بصيغة ELF باستخدام \lstinline{namei()}.
\item يتفحص رأس ELF للتأكد من الماجيك هيدر الصحيح.
\item ينشئ جدول صفحات جديد فارغ للعملية باستخدام \lstinline{proc_pagetable()}.
\item يحمل أجزاء البرنامج (Program Segments) إلى الصفحات الفيزيائية المخصصة حديثًا عبر \lstinline{loadseg()}.
\item يخصص صفحة مكدس المستخدم ويدفع فيها الوسائط (\lstinline{argv}).
\item يحرر جدول الصفحات القديم والذاكرة القديمة عبر \lstinline{proc_freepagetable()}.
\item يربط جدول الصفحات الجديد بالعملية ويثبت نقطة الدخول \lstinline{epc}.
\end{enumerate}

\section{العالم الحقيقي}

تستخدم أنظمة التشغيل الحديثة آليات ذاكرة افتراضية متطورة للغاية متل:
\begin{itemize}
\item \textbf{النسخ عند الكتابة (Copy-on-Write - COW)}: مشاركة الصفحات الفيزيائية بين الأب والابن عند \lstinline{fork()} ونساخها فقط عند محاولة التعديل.
\item \textbf{الصفحات الضخمة (Superpages)}: استخدام صفحات بحجم 2 ميجابايت أو 1 جيجابايت لتقليل الضغط على مخزن الترجمة المؤقت.
\item \textbf{التصفح بالمطالبة (Demand Paging) والتبديل (Swapping)}: نقل الصفحات إلى القرص الصلب عند امتلاء الذاكرة الفيزيائية.
\end{itemize}

\section{تمارين}

1. اشرح لماذا تحتاج النواة إلى صفحة المنصة القافزة \lstinline{TRAMPOLINE} في نفس العنوان الافتراضي لدى جميع العمليات والنواة.
2. قم بتنفيذ آليات تخصيص الصفحات الكبيرة لتقليل عدد مستويات جداول الصفحات في xv6.
