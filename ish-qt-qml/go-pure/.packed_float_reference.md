# Packed floating-point conversion reference

## CVTPS2PD

Source: [Felix Cloutier — CVTPS2PD](https://www.felixcloutier.com/x86/cvtps2pd)

The legacy SSE encoding is `0F 5A /r`: `CVTPS2PD xmm1, xmm2/m64`. It converts two packed IEEE-754 single-precision values from the low 64 bits of an XMM register or from a 64-bit memory source into two double-precision values in the destination XMM register. In legacy SSE, the source is XMM or m64 and the destination is XMM; the architectural model used here has only 128-bit XMM state, so the two converted 64-bit lanes fill all 16 destination bytes. Conversion follows the normal floating-point conversion behavior and does not modify RFLAGS.

## CVTPD2PS

Source: [Felix Cloutier — CVTPD2PS](https://www.felixcloutier.com/x86/cvtpd2ps)

The legacy SSE encoding is `66 0F 5A /r`: `CVTPD2PS xmm1, xmm2/m128`. It converts two packed double-precision values from an XMM register or 128-bit memory source into two single-precision values in the low 64 bits of the destination XMM register. The legacy SSE operation explicitly zeroes destination bits 127:64. Inexact conversion is rounded according to the MXCSR rounding control; this JIT's current floating-point model uses Go's IEEE conversion path and must preserve the existing policy for floating-point exception state. RFLAGS are unchanged.

The implementation must snapshot the source before writing the destination so register aliasing is safe. REX.R selects XMM8–XMM15 in 64-bit legacy SSE forms.

## Planned CVTTPD2DQ

The truncating packed double-to-signed-doubleword conversion will use its legacy SSE form and must use truncation toward zero rather than the current rounding mode. The result is a packed signed 32-bit integer vector, with invalid/out-of-range inputs following the instruction's architectural indefinite-integer behavior. The implementation should verify the exact legacy destination width and upper-lane semantics from the Intel/Felix reference before coding.

## CVTTPD2DQ

Source: [Felix Cloutier — CVTTPD2DQ](https://www.felixcloutier.com/x86/cvttpd2dq)

The legacy SSE encoding is `66 0F E6 /r`: `CVTTPD2DQ xmm1, xmm2/m128`. It converts two packed doubles from an XMM register or 128-bit memory source to two signed 32-bit integers in the low 64 bits of the destination XMM register. The legacy operation explicitly sets destination bits 127:64 to zero. Inexact values are truncated toward zero. If a result is outside the signed 32-bit range, or otherwise invalid such as NaN, the masked floating-point invalid result is the indefinite integer `0x80000000` for that lane. RFLAGS are unchanged. REX.R selects extended XMM registers in 64-bit legacy forms.

The exact legacy pseudocode is:

```text
DEST[31:0]   := Convert_Double_Precision_Floating_Point_To_Integer_Truncate(SRC[63:0])
DEST[63:32]  := Convert_Double_Precision_Floating_Point_To_Integer_Truncate(SRC[127:64])
DEST[127:64] := 0
```
