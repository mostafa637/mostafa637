# Non-temporal store reference — GPR/MMX

المراجع:

- [Felix Cloutier — MOVNTI](https://www.felixcloutier.com/x86/movnti)
- [Felix Cloutier — MOVNTQ](https://www.felixcloutier.com/x86/movntq)

## MOVNTI

الصيغة `0F C3 /r` هي `MOVNTI m32, r32`، ومع `REX.W` تصبح `MOVNTI m64, r64`. destination هو memory-only ModRM.r/m، والمصدر GPR في ModRM.reg؛ في 64-bit mode يسمح REX.R بسجلات R8–R15 وREX.W يختار عرض 64-bit. العملية `DEST := SRC`، ولا تعدّل flags. في JIT لا توجد cache hierarchy، لذا يكفي store عادي مع الحفاظ على fault semantics للذاكرة.

## MOVNTQ

الصيغة `0F E7 /r` هي `MOVNTQ m64, mm`. destination memory-only بعرض 8 bytes والمصدر MMX، والعملية `DEST := SRC` دون نتيجة register أو تغيير flags. يجب أخذ snapshot لقيمة MMX قبل محاولة الكتابة، ثم استدعاء `EnterMMX` بعد نجاح الكتابة؛ فالتعليمة جزء من مسار MMX في نموذج الحالة الحالي وتعيد TOP إلى الصفر كما تفعل تعليمات MMX الأخرى.

## قرار التنفيذ

سيُفصل اتجاه operand عن MOVNTDQA/MOVNTDQ: هذه المجموعة store إلى memory فقط، ولذلك يجب رفض register destination أثناء compile. ستُستخدم read source ثم writeOperand64، بحيث تنتقل أخطاء الصفحة/الحماية من memory model إلى الـJIT كما في بقية stores.

## MOVNTPD

مرجع [MOVNTPD](https://www.felixcloutier.com/x86/movntpd) يعرّف legacy `66 0F 2B /r` كـ`MOVNTPD m128, xmm1`. destination memory-only بعرض 16 bytes والمصدر XMM، والعملية `DEST := SRC`، دون flags أو نتيجة register. النسخة legacy تتطلب محاذاة 16-byte وفق المرجع؛ نموذج JIT الحالي يجب أن يحافظ على fault semantics الموجودة في writeOperand64، بينما لا توجد cache hierarchy guest.

## MOVNTSD/MOVNTSS

صفحات Felix Cloutier المستقلة لهذين الاسمين غير متاحة في المسار المتوقع، لذلك يجب تثبيت الترميز والدلالة من جداول x86asm ومرجع Intel/تعليمات MOVSD/MOVSS: legacy scalar non-temporal stores تكتب فقط low 64-bit (MOVNTSD) أو low 32-bit (MOVNTSS) إلى memory، مع memory-only destination، ولا تغيّر source XMM أو flags. لا ينبغي الخلط بينها وبين MOVSD/MOVSS load/store العادية التي قد تملك register destinations.
