## ABI facts used by the Pure-Go implementation

The x86-64 `getdents64` record is `linux_dirent64`:

```c
struct linux_dirent64 {
    ino64_t        d_ino;
    off64_t        d_off;
    unsigned short d_reclen;
    unsigned char  d_type;
    char           d_name[];
};
```

The fixed prefix is 19 bytes: `d_ino` at offset 0, `d_off` at offset 8, `d_reclen` at offset 16, `d_type` at offset 18, and the NUL-terminated name at offset 19. Records are padded to the record alignment used by the ABI; this implementation uses 8-byte alignment, matching the existing i386 directory-entry builder and the x86-64 field widths.

The syscall returns the number of bytes written, returns zero at end-of-directory, returns `EBADF` for an invalid descriptor, `EFAULT` for an invalid guest buffer, `EINVAL` when the supplied buffer cannot hold even the next record, and `ENOTDIR` when the descriptor does not reference a directory. The count argument is an unsigned integer and Linux assumes it does not exceed `INT_MAX`.

`d_type` values are the standard `DT_*` values: unknown 0, FIFO 1, character device 2, directory 4, block device 6, regular file 8, symlink 10, and socket 12. `d_off` is an opaque directory-cookie value; the Pure-Go fakefs implementation uses the next logical entry index as its stable cookie and stores the current index in `corefd.File.DirPos`.
