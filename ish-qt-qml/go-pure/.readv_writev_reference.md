## Semantics used by the Pure-Go ABI64 implementation

`readv(fd, iov, iovcnt)` scatters input into the iovec entries, while `writev` gathers output from them. The entries are processed strictly in array order: each entry is completed before proceeding to the next, and a short read/write stops the sequence. The return value is the total number of bytes transferred, or a negative errno value on failure.

On x86-64, each `struct iovec` is 16 bytes: `iov_base` is an unsigned pointer-sized value at offset 0 and `iov_len` is an unsigned `size_t` at offset 8, both little-endian. The implementation validates `iovcnt`, protects multiplication when reading the array, rejects a sum that exceeds the guest transfer budget or signed return range with `EINVAL`, and maps inaccessible iovec metadata or buffers to `EFAULT`.

The handlers use the same descriptor Reader/Writer semantics as read(2)/write(2). A partial transfer returns the accumulated byte count when a later segment fails after progress, matching the existing i386 implementation and Linux's short-I/O behavior.
