# statx ABI reference

Sources:

- https://man7.org/linux/man-pages/man2/statx.2.html — `statx(2)`, Linux manual page.
- https://man.archlinux.org/man/statx.2.en — `statx(2)`, Arch manual page mirror.

## x86-64 layout

The Linux `struct statx` returned by `statx(2)` is 256 bytes. The fixed fields are laid out as follows:

- offset 0: `stx_mask` (`u32`)
- offset 4: `stx_blksize` (`u32`)
- offset 8: `stx_attributes` (`u64`)
- offset 16: `stx_nlink` (`u32`)
- offset 20: `stx_uid` (`u32`)
- offset 24: `stx_gid` (`u32`)
- offset 28: `stx_mode` (`u16`), followed by 2 bytes padding
- offset 32: `stx_ino` (`u64`)
- offset 40: `stx_size` (`u64`)
- offset 48: `stx_blocks` (`u64`)
- offset 56: `stx_attributes_mask` (`u64`)
- offset 64, 80, 96, 112: `statx_timestamp` values for atime, btime, ctime, mtime; each timestamp is 16 bytes with signed `tv_sec` at +0, `tv_nsec` at +8, and reserved/padding bytes at +12..15
- offset 128: `stx_rdev_major` (`u32`)
- offset 132: `stx_rdev_minor` (`u32`)
- offset 136: `stx_dev_major` (`u32`)
- offset 140: `stx_dev_minor` (`u32`)
- offset 144: `stx_mnt_id` (`u64`)
- offset 152: `stx_dio_mem_align` (`u32`)
- offset 156: `stx_dio_offset_align` (`u32`)
- offset 160: `stx_subvol` (`u64`)
- offset 168: `stx_atomic_write_unit_min` (`u32`)
- offset 172: `stx_atomic_write_unit_max` (`u32`)
- offset 176: `stx_atomic_write_segments_max` (`u32`)
- offset 180: `stx_dio_read_offset_align` (`u32`)
- offset 184: `stx_atomic_write_unit_max_opt` (`u32`)
- offsets 188..255: reserved bytes

Each `statx_timestamp` has a signed 64-bit seconds field and an unsigned 32-bit nanoseconds field. The returned `stx_mask` communicates which fields were filled; it need not equal the requested mask. The basic mask is the OR of TYPE, MODE, NLINK, UID, GID, ATIME, MTIME, CTIME, INO, SIZE, and BLOCKS.

## Scope for this implementation

The Pure-Go fakefs exposes mode, UID, GID, device, inode, size, and modification time. The handler will therefore populate basic metadata and mtime, return a conservative supported mask, set unsupported timestamps/fields to zero, accept `AT_FDCWD`, absolute/relative paths, and `AT_SYMLINK_NOFOLLOW`, and reject unsupported flags with `EINVAL`. Guest memory failures return `EFAULT`; missing paths return `ENOENT`.
