# SHA SIMD reference

Sources: [SHA1MSG1](https://www.felixcloutier.com/x86/sha1msg1), [SHA1MSG2](https://www.felixcloutier.com/x86/sha1msg2), [SHA256MSG1](https://www.felixcloutier.com/x86/sha256msg1), [SHA256MSG2](https://www.felixcloutier.com/x86/sha256msg2), [SHA256RNDS2](https://www.felixcloutier.com/x86/sha256rnds2), and [Intel SHA Extensions](https://www.intel.com/content/dam/develop/external/us/en/documents/intel-sha-extensions-white-paper-402097.pdf).

All five legacy SHA instructions use XMM destination/source1 and XMM or m128 source2, preserve flags, and write a full 128-bit XMM result. The x86asm v0.30.0 package defines SHA1MSG1, SHA1MSG2, SHA256MSG1, SHA256MSG2, and SHA256RNDS2; JIT64 currently has no dispatch for them.

SHA1MSG1 treats four big-endian dwords as W0..W3 from SRC1[127:96] through SRC1[31:0], and W4..W5 as SRC2[127:96] and SRC2[95:64]. It writes `[W2 xor W0, W3 xor W1, W4 xor W2, W5 xor W3]` in descending bit order. SHA1MSG2 reads W13..W15 from SRC2[95:64], [63:32], [31:0], then computes W16=(SRC1[127:96] xor W13) rol1, W17=(SRC1[95:64] xor W14) rol1, W18=(SRC1[63:32] xor W15) rol1, and W19=(SRC1[31:0] xor W16) rol1; it stores W16..W19 in descending bit order.

SHA256MSG1 reads W4=SRC2[31:0] and W3..W0 from SRC1[127:96] through SRC1[31:0]. It writes `[W3 + sigma0(W4), W2 + sigma0(W3), W1 + sigma0(W2), W0 + sigma0(W1)]` in descending bit order, modulo 2^32. SHA256MSG2 reads W14=SRC2[95:64] and W15=SRC2[127:96]. It computes W16=SRC1[31:0]+sigma1(W14), W17=SRC1[63:32]+sigma1(W15), W18=SRC1[95:64]+sigma1(W16), W19=SRC1[127:96]+sigma1(W17), then stores `[W19,W18,W17,W16]` in descending bit order.

For SHA-256, sigma0(x) = ROTR7(x) XOR ROTR18(x) XOR (x >> 3), and sigma1(x) = ROTR17(x) XOR ROTR19(x) XOR (x >> 10). The instruction pages use big-endian lane notation even though XMM bytes are stored little-endian; implementation must read dwords in the instruction's lane order, which corresponds to little-endian uint32 at byte offsets 0,4,8,12 when applying the listed lane positions carefully.


SHA256RNDS2 has an implicit XMM0 source and uses only XMM0 dwords 0 and 1 as WK0/WK1. Source1 supplies C,D,G,H and source2 supplies A,B,E,F in the reference's big-endian lane notation. For each of two rounds, T1 = Ch(E,F,G)+Sigma1(E)+WK_i+H and T2 = Maj(A,B,C)+Sigma0(A); the next state is A=T1+T2, B=old A, C=old B, D=old C, E=T1+old D, F=old E, G=old F, H=old G. The destination stores only A2,B2,E2,F2 in the four dword lanes; flags are unchanged. Sigma0(x)=ROTR2(x)^ROTR13(x)^ROTR22(x), Sigma1(x)=ROTR6(x)^ROTR11(x)^ROTR25(x), Ch(x,y,z)=(x&y)^((^x)&z), and Maj(x,y,z)=(x&y)^(x&z)^(y&z), all modulo 2^32.

The Intel SHA Extensions white paper confirms that the SHA instructions are 128-bit SSE operations with non-SIMD dword semantics and describes the message schedule and rounds mapping. SHA1RNDS4 and SHA1NEXTE are not in x86asm v0.30.0's SHA constants found in this project, so this phase targets the five available SHA1/SHA256 operations only.
