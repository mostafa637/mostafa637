# AES-NI reference

Sources: [AESENC](https://www.felixcloutier.com/x86/aesenc), [AESENCLAST](https://www.felixcloutier.com/x86/aesenclast), [AESDEC](https://www.felixcloutier.com/x86/aesdec), [AESDECLAST](https://www.felixcloutier.com/x86/aesdeclast), [AESIMC](https://www.felixcloutier.com/x86/aesimc), and [AESKEYGENASSIST](https://www.felixcloutier.com/x86/aeskeygenassist).

This phase targets legacy SSE encodings only. The legacy AESENC/AESENCLAST/AESDEC/AESDECLAST forms require destination XMM to also be the first source, and accept an XMM or m128 second source. AESENC applies ShiftRows, SubBytes, MixColumns, then XORs the round key; AESENCLAST omits MixColumns. AESDEC applies InvShiftRows, InvSubBytes, InvMixColumns, then XORs the round key; AESDECLAST omits InvMixColumns. These instructions do not modify flags and write all 128 destination bits.

AES state byte mapping follows the AES-NI byte-oriented transformation defined by Intel. Implementations must use the exact AES state mapping rather than treating XMM as four independent integer lanes. SubBytes uses the AES S-box and InvSubBytes the inverse S-box. ShiftRows rotates AES state rows by row index, and MixColumns applies the GF(2^8) matrix [02 03 01 01; 01 02 03 01; 01 01 02 03; 03 01 01 02] to each column. Inverse MixColumns uses [0e 0b 0d 09; 09 0e 0b 0d; 0d 09 0e 0b; 0b 0d 09 0e].

AESIMC performs InvMixColumns on each of the four 32-bit words of an XMM source and writes the full XMM result; it does not modify flags. AESKEYGENASSIST takes an XMM/m128 source plus imm8. It computes SubWord and RotWord(SubWord) for source dwords X1 and X3, writes both 64-bit result halves, and XORs the zero-extended imm8 round constant into the rotated words. The exact dword mapping is recorded below from Intel's pseudo-code.

The x86asm v0.30.0 tables define AESENC, AESENCLAST, AESDEC, AESDECLAST, AESIMC and AESKEYGENASSIST. This phase adds dispatch and Pure Go micro-ops for all six legacy instructions.


AESIMC is simply `DEST[127:0] := InvMixColumns(SRC)` for the legacy 128-bit form. AESKEYGENASSIST uses source dwords X0=SRC[31:0], X1=SRC[63:32], X2=SRC[95:64], X3=SRC[127:96], and RCON=zero-extended imm8. The exact destination dwords are: DEST lane 0 = SubWord(X1); lane 1 = RotWord(SubWord(X1)) XOR RCON; lane 2 = SubWord(X3); lane 3 = RotWord(SubWord(X3)) XOR RCON. Both halves are always produced; imm8 is not a selector. The legacy form preserves any upper YMM state, which is outside MachineState64's XMM-only model.
