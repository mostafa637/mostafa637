# Legacy SSE half-register move semantics

Sources:
- https://www.felixcloutier.com/x86/movhlps
- https://www.felixcloutier.com/x86/movlhps

## MOVHLPS xmm1, xmm2

Legacy two-operand form is register-only: ModRM.MOD must be 011b; memory-to-register encoding is not valid. The operation copies SRC[127:64] into DEST[63:0] and leaves DEST[127:64] unchanged. No flags are modified.

## MOVLHPS xmm1, xmm2

Legacy two-operand form is register-only: ModRM.MOD must be 011b; memory-to-register encoding is not valid. The operation copies SRC[63:0] into DEST[127:64] and leaves DEST[63:0] unchanged. No flags are modified.

The JIT must snapshot both source and destination before writing when aliases are possible. In the legacy form, destination is an XMM register and source must be an XMM register; the VEX/EVEX three-operand forms are outside this legacy x86asm/JIT64 scope.

## MOVHPD and MOVHPS

Legacy loads use an XMM destination and a 64-bit memory source. They copy source[63:0] into destination[127:64] and preserve destination[63:0]. Legacy stores use a 64-bit memory destination and an XMM source, copying source[127:64] to memory[63:0]. Register-to-register and memory-to-memory forms are invalid for these legacy load/store opcodes. No flags are modified. MOVHPD uses the 66 prefix and MOVHPS uses the unprefixed opcode; both have the same bit-level behavior in this model.

## MOVLPD and MOVLPS

Legacy loads use an XMM destination and a 64-bit memory source. They copy source[63:0] into destination[63:0] and preserve destination[127:64]. Legacy stores use a 64-bit memory destination and an XMM source, copying source[63:0] to memory[63:0]. Register-to-register and memory-to-memory forms are invalid for these legacy load/store opcodes. No flags are modified. MOVLPD uses the 66 prefix and MOVLPS uses the unprefixed opcode; their bit-level behavior is identical here.
